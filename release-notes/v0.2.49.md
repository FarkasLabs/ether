This release lets owners rank releases with rules they type, record one
device's problem as a redacted support archive, and corrects health, new
seasons, Home rows, and several playback and library gates.

## New and improved

- **Release preferences:** on **Releases → Quality profiles**, edit a profile
  and type terms to require, prefer, or avoid. A term can be a language, a
  tag, a release group, a codec, or any other text. Order is priority.
  Preview the draft against pasted filenames, or search a title to include
  the rest of the quality rules. Import and export the list. The rules are
  part of the profile, so editing them forgets the release Ether had
  remembered for that profile. The title's original language is used only
  while ranking that title. Changing it forgets a remembered release that
  was chosen with an original-language rule (#156).
- **Integrations as brand cards:** the Integrations page shows each service
  as a brand card. Turning a card on walks through setup, and the service
  stays off until that setup is saved. The new copy is translated in the
  owner-console catalogues (`feat/integrations-public`).
- **Record a problem:** from Logs, or from command search, record one device
  and download a single redacted support ZIP (`ether.support.v1`). An
  unknown device is not selected for you. A capture that only saw polls
  says no playback request was observed. Titles, usernames, and addresses
  are separate opt-ins, and the finish preview names the identity that
  will be in the archive. Review the ZIP before sharing (#151).
- **New seasons of returning shows:** a returning series, including its
  season list, is refreshed within an hour instead of waiting out the
  24-hour catalogue refresh. Reported on Reddit for *Dexter: Resurrection*
  season 2 (#148).

## Playback and library

- **Unlabelled WEB releases and a 4K floor:** a WEB-DL or WEBRip with no
  resolution in the name counts as SD (480) against the profile minimum.
  That stops an SD WEB release winning when the 4K copy cannot play for
  the client. Reported on Reddit for *Coyote vs. Acme*. Unlabelled HDTV
  and DVD rips stay exempt. An explicit version pick or a pin still
  bypasses the floor (#149).
- **Home rows:** empty Continue Watching, in-progress, and
  viewer-restricted hubs are left out, so Plex for Android no longer
  receives blank rows at the top of Ether's Home. Personalised order stays
  put for one viewer, library surface, and device class until browsing is
  idle for five minutes or the day changes. A repeated hub is listed once.
  Personalised ranking itself is unchanged. A phone build and a Shield
  sitting have not been checked yet (#155, #150).
- **Android audio and subtitle choices, in part:** after a title has been
  played, the decision for that viewer keeps the other audio and subtitle
  tracks from the release they would play, instead of falling back to a
  one-audio estimate. The first open, before Ether has a resume row for
  that title, still has no real track list. #145 stays open
  (`fix/issue-145-android-tracks`).
- **Director disclaimers:** a movie release named like
  `Title 2026 NOT The <Director> FILM` is rejected when that director is
  the catalogue director of the title being resolved. The complete name is
  required. Episodes are unchanged (#154).
- **VAAPI when GPU scaling is unavailable:** if `scale_vaapi` fails a
  one-frame probe, VAAPI sessions decode and scale in software and upload
  frames to the hardware encoder, instead of failing the hardware path and
  transcoding every ladder rung on the CPU. This has automated coverage
  only. No live GPU result is claimed, and the #13 reporter has been asked
  for `vainfo` output (#153, #13).
- **Content ratings:** a content-rating rule set to "is none of" also hides
  titles with no rating, so a missing certification cannot slip past an
  allowlist. Unknown country, genre, year, and language still do not match
  an exclusion. A known local rating still wins over an incomplete remote
  summary (`e7fb04e2`).
- **Health behind a reverse proxy:** an installed, unexpired certificate
  that Ether has not trust-checked stays "Not verified", and that row no
  longer holds the whole server at "Status incomplete." A configured
  direct route and a published custom route are labeled separately.
  Neither label means Ether has proved the server is reachable from
  outside. Missing validity dates, real expiry, renewal, sign-in, and
  publishing failures still count (#146, #144).

## After upgrading

- Reload an already-open owner console to use Release preferences, the
  Integrations cards, and Record a problem.
- If a library uses a content-rating "is none of" rule, unrated titles in
  that library are now hidden. Confirm that is what you want.
- #144 can be checked on the reverse-proxy server that reported a permanent
  "Status incomplete." The certificate row remains "Not verified."

## Known limits

No live GPU confirmation for the VAAPI scale probe. #145's first open,
before any resume row, still has no real tracks. Prism, Jellyfin client
support, and watch-state sync are not in this release. The Integrations
cards are the owner console only.

Importing a large watch history from another Plex server (#152, reported
by @FizzWhirl) is not in this draft. A fix from the same work as the
content-rating change was considered and is **TBD**.
